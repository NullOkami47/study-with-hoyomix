# Community Chat design contract

## 2026-10-17 Community study lounge

The existing floating Liquid Glass window remains the only chat surface. Its drag, resize, protected-player collision and narrow sheet geometry remain authoritative. Control Centre contains an explanation and open/focus commands; it never mounts another transport. Chat starts hidden on each fresh visit, connects only while mounted and releases its socket on close. Draft text belongs to the workspace session, surviving a close without storing public messages locally.

Chat uses the existing primary/muted text, opaque surface, glass-border, focus-ring, radius-control and motion-duration tokens. Compact metadata rows distinguish initials, author, server role, opt-in localised country and timestamp. Message text wraps and preserves line breaks, never HTML. The message area alone scrolls inside a flex column; the composer remains a separate shrinking-safe row. Older history preserves its scroll anchor, near-bottom readers follow live messages, and readers further up receive a jump-to-latest command. Restrained icon stickers are original compositions from the installed Lucide library (tea, focus, cheer, rest); copyrighted reference stickers are not copied.

Anonymous readers see an account command. Posting, editing, deleting, reporting and blocking use native labelled controls with 44px targets and visible focus. The non-modal window never traps focus. Connection status is polite, while the message log avoids announcing history floods. Reconnection disables sending until a verified snapshot arrives; failed sends retain the draft and never appear as successful messages. Country display is optional and server-derived, with neutral unknown fallback. Track cards use canonical catalogue IDs and explicit Play/Add to queue commands, with a readable unavailable state in an empty catalogue. No artwork source exists in the current Track model, so cards use the existing music icon fallback.

Visual verification must cover signed-out, connected, disconnected, populated/history, editing, sticker and unavailable-track states at desktop, tablet and narrow widths, including short landscape. Keyboard composition must preserve CJK Enter and Shift+Enter. No new colour, animation runtime, external asset, font or analytics dependency is introduced.

Chat moderation in AdminShell reuses the existing opaque glass form surfaces and semantic text tokens. Report, ban, filter and audit primitives have labelled native inputs, wrapping content, explicit empty/error states, a 44px minimum target, global focus-visible ring and tokenised hover/active feedback. Administrative commands remain subordinate to server RBAC; loading and server acknowledgement determine success. Moderator navigation uses the explicit `/admin#admin-chat` destination rather than creating an independent administrative session.
